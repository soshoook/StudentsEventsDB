## Состав проекта

| Файл | Назначение |
|---|---|
| `Event.java` | Модель данных: одно мероприятие |
| `Field.java` | Enum полей (ID, NAME, DESCRIPTION, DATE, START_TIME, END_TIME, TYPE, STATUS) для поиска и индексов |
| `HashIndex.java` | Хеш-индекс на диске для одного поля |
| `FileStorage.java` | Ядро базы: записи, добавление, поиск, удаление, обновление |
| `Main.java` | Графический интерфейс (Swing) |

## Главные идеи

### 1. Записи фиксированного размера

Каждая запись занимает ровно **274 байта**, поэтому позиция записи в файле считается по формуле:

```
позиция = 8 + номер_слота * 274
```

Файл `events.db`:

```
[заголовок: slotCount(4) + nextId(4)] [запись 0] [запись 1] ...
```

Структура записи:

| Часть | Байт |
|---|---|
| id | 4 |
| name | 20 |
| description | 200 |
| date (дни с 1970-01-01, long) | 8 |
| start_time | 5 |
| end_time | 5 |
| type | 30 |
| status | 1 |
| флаг удаления | 1 |

Строки хранятся в UTF-8 и дополняются нулевыми байтами. Лимит считается в **байтах**: кириллица занимает 2 байта на символ, поэтому в `name` помещается 10 русских букв.

### 2. Хеш-индекс на каждое поле

Для каждого из 8 полей есть свой файл индекса (`HashIndex`):

```
[65536 корзин по 4 байта: head] [узел слота 0: prev, next] [узел слота 1] ...
```

- Значение поля превращается в номер корзины через `hashCode()` (с перемешиванием битов и маской `& 0xFFFF`).
- В корзине хранится номер первого слота цепочки.
- Цепочка двусвязная (`prev`/`next`), поэтому вставка и удаление выполняются за **O(1)**.
- Коллизии разрешаются проверкой: после поиска по цепочке `FileStorage` сверяет точное значение поля в самой записи.

### 3. Мягкое удаление

Удалённая запись не стирается физически: в её последний байт пишется 1, а слот убирается из всех индексов. Удалённые слоты повторно не используются.


## Графический интерфейс

Кнопки в окне:

- **Создать / очистить**: создаёт пустую базу (с подтверждением)
- **Открыть**: открывает `events.db`
- **Добавить / Изменить / Удалить**: работа с записями (через диалоги)
- **Поиск**: выбор поля и значения, в таблице остаются только найденные записи
- **Показать все**: возвращает полный список
- **Резервная копия**: копирует базу и индексы в папку `events_backup`
- **Восстановить**: возвращает базу из резервной копии
